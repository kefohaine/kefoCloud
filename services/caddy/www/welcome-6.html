A repository that runs a domain.

There is a genre of software that promises self-hosting and delivers a weekend of YAML. This is a story about the other kind: a public repository, kefohaine/kefoserver, whose installer turns a bare Debian VPS into the stack you are reading this on — three answers, one unattended run, no weekend.

The craft is in what it refuses to leave vague. Hostnames are not configured by hand; they are derived from the domain you type at the first prompt. Certificates are not imported; they are issued per hostname through Cloudflare DNS and renewed forever. Admin passwords are not stored in files; they are printed once at creation and rotated by a make target. Nothing about the running system is a secret held outside the repository's own mechanisms.

The restraint is in what it refuses to run. Every container carries a hard RAM ceiling, so no single service can quietly eat the box. The game panel never autostarts — a reboot brings up the panel and nothing else. And a smoke test stands between every push and production: if any vhost stops serving its real application, the push simply does not happen. Drift is not tolerated; it is mechanically impossible.

"The most persuasive architecture document is a server that anyone can clone and none of us has to babysit." — the repo, demonstrating itself

You can read the whole thing before you run it — the compose files, the vhosts, the gotchas doc that grew from real incidents. That, more than any feature, is the pitch: kefohaine/kefoserver is legible. And when you are ready:

git clone https://github.com/kefohaine/kefoserver && bash install.sh

…the same fifteen minutes that built this journal issue builds yours.
